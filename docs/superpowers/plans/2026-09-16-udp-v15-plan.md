## 技术要点（调研结论）

### connected-UDP（Qt connectToHost 等价）

- **libuv**：`uv_udp_connect(handle, sockaddr)`（vendored 1.49.2 uv.h:745）——connect 后 `uv_udp_send` 的 sockaddr 参数被忽略（用已连接对端）；`connect(NULL)` 解绑。**接收**：只收来自该对端的包。
- **asio**：`udp::socket::connect(endpoint)` / `close` 解绑；connect 后 `async_send`（非 send_to）可用。
- **ICMP 语义**：connected UDP socket 收到 ICMP port unreachable → 下次 send/recv 返回 ECONNREFUSED——**映射到现有 `kConnectionRefused`**（无需新枚举）。
- **SocketState**：socket_state.hpp:41 注释早已预留「connect/connected transitions exist for datagram sockets」——启用 `kConnecting`（connect 是同步的，实际可跳过）/`kConnected`。**裁定：connect_to 同步成功直接 kIdle→kConnected**（UDP connect 无握手，kConnecting 无意义），注释同步更新。
- **交互规则**（Qt 语义）：
  - connect 后 `send_to(ip,port)` → fatal（Qt：connected socket 用 write 不用 writeDatagram）→ 我们的形态：`send()`（无参地址，走已绑定对端）+ connect 后 `send_to` fatal。
  - `disconnect_remote()` 解绑回 kBound（Qt 无此 API，我们补——Qt 靠重新 connect 另一个对端）。
  - connect 前提：必须已 kBound（或 lazy-bind），connect 到多播/广播地址 → 文档化为 UB/错误。
  - `set_on_datagram` 照常（收到的只有对端包，sender ip/port = 对端）。

### broadcast（SO_BROADCAST）

- 仅 IPv4；目的地址 255.255.255.255 或子网广播地址。
- **uv**：`uv_udp_bind` 前无 per-socket option API——libuv 不暴露 setsockopt 包装？实际上 libuv 无 broadcast 专用 API，需裸 `setsockopt(fd, SOL_SOCKET, SO_BROADCAST)`（经 `uv_fileno` 拿 fd）——**裁定：uv 侧经 native_handle 拿 fd 裸 setsockopt**（backend 内部，头文件零泄漏）。
- **asio**：`socket.set_option(asio::socket_base::broadcast(true))`——原生。
- **公共面**：`set_broadcast(bool)`——kBound 前提（bind 前设置则存 flag、bind 时应用；两后端各自实现）。
